# Architecture

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | **SvelteKit 2 + Svelte 5 (runes mode)** | Best-in-class SSR/SSG + minimal client JS = good Core Web Vitals. Runes simplify reactivity for scrollytelling state. |
| Language | **TypeScript (strict)** | Catch shape errors in chapter/data structures early. |
| Styling | **Tailwind CSS v4** with `@tailwindcss/typography` + `@tailwindcss/forms` | Utility-first + bold theme tokens in CSS-first config. |
| Animation | **GSAP 3 + ScrollTrigger** | Most robust scrollytelling engine, free since 2024, plays well with Svelte `@attach`/`$effect`. |
| Charts | **Observable Plot** + d3 | Static, beautiful, editorial defaults. |
| Icons | **lucide-svelte** | Tree-shaken, consistent stroke icons. |
| Fonts | **`@fontsource/arvo` + `@fontsource/lato`** | Self-hosted Google Fonts → no third-party DNS round-trip, best LCP. |
| Analytics | **PostHog (cookie-free, memory)** | GDPR-friendly defaults; pageviews + custom events. |
| Hosting | **Vercel** via `@sveltejs/adapter-vercel` | Zero-config preview deploys, edge-friendly. |
| Package manager | **pnpm** | Fast, content-addressed, smaller node_modules. |
| Node | **24 LTS** via `.nvmrc` | Latest stable LTS. |

## The active-explainer pattern

The big architectural choice: a **single** `ActiveExplainer` Svelte context that the layout provides, each explainer page sets, and every shared component (Nav, ProgressBar, viz charts, SourceSheet, EssayFooter) reads.

```ts
// $lib/context/explainer.svelte.ts (truncated)
class ExplainerHolder { current = $state<ActiveExplainer | null>(null); }

export function provideExplainerHolder(): ExplainerHolder;  // called once in +layout.svelte
export function activateExplainer(value: ActiveExplainer): () => void;  // returns cleanup for onDestroy
export function getActiveExplainer(): ActiveExplainer | null;  // reactive read
```

```svelte
<!-- src/routes/explainers/ultra-processed/+page.svelte -->
<script>
  import { onDestroy } from 'svelte';
  import { activateExplainer } from '$lib/context/explainer.svelte';
  import { ultraProcessed } from '$lib/explainers/ultra-processed';
  onDestroy(activateExplainer(ultraProcessed));
</script>
```

The trade-off vs a dynamic `[slug]` route is that each essay can deviate freely in layout / hero / closing — we pay one new route folder per essay.

## Conventions

### Naming

- **Components**: `PascalCase.svelte` (e.g. `StatCard.svelte`, `Scrolly.svelte`).
- **Modules / utilities**: `kebab-case.ts` (e.g. `cn.ts`, `image-manifest.ts`).
- **State modules** (need runes): `kebab-case.svelte.ts` (e.g. `explainer.svelte.ts`).
- **Data files**: lowercase singular nouns: `chapters.ts`, `sources.ts`.

### Components

- Always Svelte 5 runes: `$props`, `$state`, `$derived`, `$effect`.
- Prefer `{@attach ...}` over `use:` for new code (Svelte ≥ 5.29).
- Every component documents its props at the top of `<script>`.

### State for scrollytelling

- Use **Svelte 5 runes** for local reactivity. Avoid stores unless cross-route.
- **GSAP ScrollTrigger** owns the scroll-to-state mapping. Components subscribe via `@attach` factories that return cleanup functions.

### Styling

- Theme tokens are declared in `src/lib/styles/app.css` inside `@theme { … }` (Tailwind v4 CSS-first config).
- One global stylesheet, imported from `+layout.svelte`.

### Accessibility

- Always semantic HTML.
- Every scrollytelling reveal must have a non-animated fallback for `prefers-reduced-motion`.
- One `<h1>` per page, `<h2>` per chapter, `<h3>` per sub-section.

### Performance

- Self-host fonts via `@fontsource/*`.
- Lazy-import GSAP plugins inside the attachment factory.
- Use `<svelte:head>` for per-route SEO + Open Graph.

## Data model — shared

```ts
// src/lib/types/explainer.ts
export interface Chapter { id; number; eyebrow; emoji?; title; shortTitle?; intro; accent; steps: Step[]; sources?: string[]; }
export interface Step { id; text; richText?; stat?: Stat; quote?: Quote; viz?: VizConfig; }
export type VizConfig = ImageViz | BarViz | BubbleViz | LineViz | DonutViz | ObsBarViz | ObsTimelineViz;
export interface Source { id; short; full; url?; year; references?: { citation; url? }[]; }
export interface Term { id; name; short; long; url?; urlLabel?; }
export interface ImageEntry { name; width; height; blurhash; variants: { width; src }[]; credit?; }
```

## Deployment

- Push to `main` → automatic Vercel production deploy on the linked project.
- PRs get preview URLs.
- Env vars (`PUBLIC_POSTHOG_KEY`, `PUBLIC_POSTHOG_HOST`, `POSTHOG_PERSONAL_API_KEY`) are set in the Vercel dashboard.
- `pnpm run build` must pass locally before push.
